# 服务端曝光清单与反馈归因校验

本增量关闭了反馈接口原先信任客户端 `request_id/exposure_id` 的缺口。系统只接受能够与服务端真实结果清单建立完整关联的行为事件。

## 生成链路

已登录用户同时满足以下条件时，Runtime 在发送 `result` 前登记曝光清单：

1. 查询返回至少一个通过目录与硬约束复核的商品；
2. 用户已开启 `behavior_storage_enabled`；
3. 请求携带稳定的 `user_id`。

每个结果项会增加：

```json
{
  "exposure_id": "服务端生成的批次 ID",
  "position": 0
}
```

Receipt 同时保存 `exposure_id`，便于从请求审计记录追踪到曝光清单。匿名或未授权请求不会生成曝光数据，也不会在结果中返回这两个字段。

## 校验规则

`POST /agent/feedback` 写入前依次验证：

- 租户中存在该 `exposure_id`；
- `user_id`、`session_id`、`request_id` 与曝光一致；
- Item 确实出现在该曝光批次；
- 客户端位置与服务端位置一致；
- 行为发生时间不早于曝光时间，允许五分钟客户端时钟偏差。

召回来源和模型版本不使用客户端值，而是由服务端曝光清单覆盖。任一关联条件失败返回 HTTP 409，事件不会写入行为存储。

## 删除传播

删除 Profile 时会依次清理：

- 用户行为事件；
- 服务端曝光清单；
- 长期 Profile。

删除操作不依赖当前 Consent，确保用户撤回授权后仍可清理历史数据。

## 新增文件职责

- `src/seekora_agent/domain/exposure.py`：定义曝光批次和批次内商品位置、召回来源等服务端真值。
- `src/seekora_agent/application/exposure.py`：定义存储端口，实现授权登记、反馈关联校验、归因标准化和删除传播。
- `tests/test_exposure.py`：覆盖未授权不登记、归因标准化、身份/商品/位置校验、时钟偏差和删除隔离。
- `docs/01-architecture/exposure-validation.md`：说明曝光生成、反馈校验、删除规则和当前边界。

## 当前边界

- 曝光清单仍保存在单进程内存中；
- 当前以 Runtime 生成结果作为“已曝光”，尚未接收浏览器可见性确认；
- 尚未实现消息队列、迟到事件水位线、重放、机器人过滤和归因窗口；
- 五分钟只处理客户端时钟偏差，不代表完整迟到事件策略。
